# Мониторинг сайтов группы

Проект модуля 3 курса Angular и React. Сводка показывает доступность по последней проверке и долю успешных проверок. На странице сайта видны история, время ответа, заголовок HTML и оценки Lighthouse.

- [Открыть мониторинг](https://aizenrix.github.io/monitoring1/)
- [Ночная проверка](https://github.com/Aizenrix/monitoring1/actions/workflows/check.yml)
- [Сдача в репозитории курса](https://github.com/Aizenrix/angular/tree/main/projects/p3-monitoring)

В `public/data/sites.json` пока пять демонстрационных адресов. Для списка группы замените их адресами GitHub Pages однокурсников, сохраните уникальные латинские `id` и уберите поле `demo`.

## Локальный запуск

Требуется Node.js 22.22+ или Node.js 24 LTS.

```sh
npm ci
npm run dev
npm run build
npm run lint
npm test
npm run preview
```

Сайт предпросмотра открывается по пути `/monitoring1/`. `npm run check` записывает результаты локально. Для оценки Lighthouse запустите `npx playwright install --no-shell chromium`, затем `npm run audit:sites`. Оцениваются сайты, открывавшиеся в последней проверке.

## GitHub Actions

- Ночная проверка запускается в 00:00 МСК или вручную. GitHub может задержать старт. Успехом считается HTTP 2xx после перенаправлений. История ограничена 30 проверками. Сообщение Telegram отправляется только при новом сбое или восстановлении.
- Понедельничная сводка в 09:00 МСК считает сбои по каждому сайту за последние семь проверок. В понедельник в 08:00 МСК отдельно обновляются оценки Lighthouse.
- GitHub Pages использует GitHub Actions как источник. После коммита бота конвейер явно вызывает публикацию. `404.html` содержит приложение и открывает прямые маршруты с HTTP 404.
- Настройки Actions читают секреты `TELEGRAM_TOKEN` и `TELEGRAM_CHAT_ID`. Локально без секретов монитор сохраняет результаты без отправки.
